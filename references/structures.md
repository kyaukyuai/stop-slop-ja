# 避けるべき構造パターン

## 二項対立（Binary Contrasts）

False drama を作る。Y を直接述べる。

| パターン | 問題 |
|:---|:---|
| 「X ではない。Y だ」 | Telegraphed reversal（予告された反転）|
| 「X ではなく Y だ」 | 同上 |
| 「X じゃなくて Y」 | 同じ構造、口語版 |
| 「X が問題ではない。Y が問題だ」 | Formulaic reframe |
| 「答えは X ではない。Y だ」 | Predictable pivot |
| 「X に見えるが、実は Y だ」 | Setup/reveal cliche |
| 「問題は X ではない。Y だ」 | Rhetorical misdirection |
| 「これは X ではなく Y にある」 | 同じ構造 |
| 「X を超えて Y へ」 | False transformation |
| 「X ではなく、むしろ Y」 | Negation-then-assertion |
| 「X だけではなく Y も」 | Additive hedge |

**書き換え方**: Y を直接述べる。「Y が問題だ」「Y が重要だ」。否定を完全に落とす。

## 否定の列挙（Negative Listing）

「これは何でないか」を 2 個以上挙げてから「これは何か」を出す rhetorical striptease。

| パターン | 問題 |
|:---|:---|
| 「X ではない。Y でもない。Z だ」 | Dramatic buildup through negation |
| 「X でもなかった。Y でもなかった。Z だった」 | 同じ構造、過去形 |

**書き換え方**: Z を直接述べる。runway は要らない。

## 演出的断片化（Dramatic Fragmentation）

句点で文を区切って疑似的な重みを作る。

| パターン | 問題 |
|:---|:---|
| 「〜。それだけだ。これがすべてだ」 | Performative simplicity |
| 「X。そして Y。そして Z」 | Staccato drama |
| 「これが unlock。〜」 | Artificial revelation |
| 「〜。そう、〜だ」 | Manufactured intimacy |

**書き換え方**: 完全な文で書く。内容を信頼する。演出は要らない。

## 修辞的お膳立て（Rhetorical Setups）

洞察を announce するだけで deliver していない。

| パターン | 問題 |
|:---|:---|
| 「もし〜だとしたら？」 | Socratic posturing |
| 「考えてみてほしい」 | Condescending prompt |
| 「ここで言いたいのは」 | Redundant preview |
| 「そしてそれでいい」 | Unnecessary permission |
| 「想像してみてほしい」 | Same as 考えてみて |

**書き換え方**: 主張を述べる。読者に結論を引き出させる。

## 無生物主語＋人間動詞（False Agency）

無生物に人間の動詞を当てる。誰がやったかを名指しすると簡潔になる。

| パターン | 問題 |
|:---|:---|
| 「議論が深まる」 | 議論は深まらない。誰かが深めた |
| 「市場が報いる」 | 市場は報いない。買い手が払う |
| 「データが教える」 | データは教えない。誰かがデータを読んで判断する |
| 「文化が変わる」 | 文化は変わらない。人が行動を変える |
| 「決断が生まれる」 | 決断は生まれない。誰かが決断する |
| 「会話が動き出す」 | 会話は動かない。誰かが steer する |
| 「結果が物語る」 | 結果は物語らない。誰かが解釈する |
| 「数字が示す」 | 数字は示さない。誰かが数字から推論する |
| 「歴史が証明する」 | 歴史は証明しない |

**書き換え方**: 人を名指しする。「チームが議論を深めた」「買い手が払う」。
特定の人がいない場合は「あなた」で読者を主語にする。

## 傍観者視点（Narrator-from-a-distance）

シーンの外から俯瞰する語り。読者を場面に置く。

| パターン | 問題 |
|:---|:---|
| 「誰も意図しなかった」 | Disembodied observation |
| 「これが起こるのは〜」 | Lecturer voice |
| 「これが〜である理由は」 | 同じ |
| 「人々は〜する傾向にある」 | Armchair sociologist |
| 「私たちは〜しがちだ」 | 同じ |
| 「人は〜するものだ」 | Generalizing voice |

**書き換え方**: 読者を部屋に入れる。「あなたが〜する場面では」「あなたが〜したとき」。

## 受動態（Passive Voice）

主語が行為者を隠す。エネルギーが落ちる。

| パターン | 修正 |
|:---|:---|
| 「X が作られた」 | 誰が作ったかを名指しする |
| 「〜と信じられている」 | 誰が信じているかを名指しする |
| 「ミスが起こされた」 | 誰がしたかを名指しする |
| 「決定が下された」 | 誰が決めたかを名指しする |
| 「〜される」「〜られる」 | 能動態に書き換える |
| 「〜となる」 | 「〜だ」「〜する」に書き換える |

**書き換え方**: 行為者を見つけ、文頭に置く。

## 文頭の Wh-スターター

| パターン | 修正 |
|:---|:---|
| 「〜とは何か」で始まる文 | 主語または動詞から始める |
| 「なぜ〜なのか」で始まる文 | 主題を直接述べる |
| 「どうして〜なのか」 | 同上 |
| 「いかに〜か」 | 同上 |
| 「どのように〜か」 | 同上 |

「〜とは何か」「なぜ〜なのか」は記事タイトルではフックとして有効。セクション内の冒頭文では restructure する。

## リズムパターン

| パターン | 修正 |
|:---|:---|
| 3 連続の同じ長さの文 | 1 文を分割または結合 |
| 段落末が必ず punchy な一行 | 終わり方を多様化 |
| エムダッシュ（——、—）の使用 | 句点・括弧・カンマに置換、完全削除 |
| 演出的断片化（短文連発） | 完全文に戻す |
| 「常に X。常に Y」型の対称 | 並列を崩す |

## 整形パターン（k16shikano japanese-tech-writing 由来）

### 一文一行

原稿本文は一文ごとに改行する。段落の区切りは空行で示す。本筋から一段外れる補足（用語の由来、定式化の名称）は本文に並べず脚注（`[^ラベル]`）に降ろす。

### 太字と「」の使い分け

| 場面 | 記法 |
|:---|:---|
| 用語を初めて定義・導入する | 太字（**契約**） |
| すでに導入した語を話題として指す・引用・通称 | 「」（「契約」） |
| 定義や分類の列挙で定義される用語 | 太字 |

### 中黒（・）の並列（register-aware）

**技術書の原稿**では日本語の並列に中黒を使わない。読点でつなぐか箇条書きにする。

| 過剰 | 修正 |
|:---|:---|
| 「設計・実装・検証」 | 「設計、実装、検証」または箇条書き |
| 「速度・品質・コスト」 | 「速度、品質、コスト」 |

ただし単一の固有名詞の内部（「クリーン・アーキテクチャ」「サンクト・ペテルブルク」「サティア・ナデラ」）では使ってよい。

**register 注記**: note 記事・ブログ・X 投稿では中黒並列は確立した表記スタイルであり、許容する（「判断・調整・承認」「土地・設備・データ」等）。この register では読点への一律置換はしない。レビュー補助として、4 語以上の長い連鎖や、固有名詞と並列が混在して読みにくい箇所だけ整える。技術書原稿でのみ読点・箇条書きを原則とする（根拠: note 記事 1 本で中黒並列が 70 件超、ほぼ全て自然な並列だった = 一律置換は register 不一致）。

### 見出しの区切り線・二要素詰め込み

見出し・コラム見出しに罫線（`─` U+2500）やダッシュ類で「種別──主題」「主題──概念」を詰め込まない。

| 過剰 | 修正 |
|:---|:---|
| 「基礎──同値関係としての分類」 | 「同値関係としての分類」 |
| 「補足──ループ不変条件と帰納法」 | 「ループ不変条件と帰納法」 |

コラム見出しも「基礎」「補足」のような種別名だけで済ませず、内容を特定する句にする。

### 用語定義の箇条書き

用語とその定義を並べる箇条書きは、区切り線ではなく全角コロンで書く。

- 悪い例: 「契約 ── 工程間で交わす取り決め」
- 良い例: 「**契約**：工程間で交わす取り決め」

## 日本語固有のパターン

### 〜的の濫用

「構造的」「本質的」「根本的」「表面的」「実用的」「決定論的」が 1 段落に 3 つ以上ある場合に削減する。

| 過剰 | 修正 |
|:---|:---|
| 「構造的な問題」 | 「組織の構造が原因だ」 |
| 「本質的に重要」 | 「中心の論点だ」 |
| 「根本的な改革」 | 「土台から作り直す」 |

### 〜という

冗長な引用句。

| 過剰 | 修正 |
|:---|:---|
| 「AI というツール」 | 「AI」 |
| 「〜という概念」 | 「〜は」 |
| 「〜という考え方」 | 「〜と考える」 |
| 「〜という形」 | 「〜として」 |

### することができる / することが重要だ

| 過剰 | 修正 |
|:---|:---|
| 「することができる」 | 「できる」 |
| 「することが重要だ」 | 「重要だ」 |
| 「することが必要だ」 | 「必要だ」 |
| 「することが求められる」 | 「求められる」 or 削除 |

### 口語的並列

「ひとつめ / ふたつめ / みっつめ / よっつめ」は字面が古風で並列の連続性が弱い。違和感を生む。

**書き換え方**: 「第 1 に、〜」「第 2 に、〜」「第 3 に、〜」「第 4 に、〜」型を使う。または番号箇条書き（`・1: 〜` / `1. 〜`）に変換する。

## カタカナ語の濫用

業務文書では特に注意。日本語訳が定着している語は日本語を使う。

| 避ける | 使う |
|:---|:---|
| エンゲージメント | 参加、関与、反応 |
| インサイト | 知見、気づき |
| コミットメント | 約束、責任 |
| アラインメント | 一致、合意 |
| ソリューション | 解決策、答え |
| イシュー | 問題、課題 |
| インパクト | 影響、効果 |
| アジェンダ | 議題、計画 |
| アサイン | 割り当て、担当 |
| バッファ | 余裕、予備 |

固有名詞・技術用語・新語はカタカナのままで OK。

## 安直なまとめ構造（章末・記事末）

| パターン | 問題 |
|:---|:---|
| 比喩でまとめる | 「両輪が揃った」「2 本の柱」「車の両輪」「2 枚の翼」 |
| 偶然を必然化 | 「揃った」「出揃った」「同じ日に」「期せずして」「奇しくも」 |
| 評価動詞で結ぶ | 「象徴する」「物語る」「示唆する」「映し出す」「浮き彫りにする」 |
| メタコメント型 | 「メッセージは短くまとまる」「結論は単純だ」 |

**正しい締め方**:
- 数字を最後の一語にする（例: 「$25M はその結果として現れる」）
- 断定で終わる（「〜だ」「〜である」）
- 観察事実だけ並べる（自家評価を加えない）
- 読者の意思決定材料を残す

**許容**（誤検出回避）:
- 受動的締め（「〜が問われている」「〜が試されている」「〜が求められている」）
- 時代論評（「AI 時代の〜」「〜時代の〜」）

これらは読者に問題提起を残す機能として有効。

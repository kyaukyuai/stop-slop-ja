# 削除すべきフレーズ

## 前置きの咳払い（Throat-Clearing Openers）

文頭や段落冒頭の announcement 句。本文から直接始める。

- 「実は」
- 「ところで」
- 「さて」
- 「結論から言うと」
- 「核心はこうだ」
- 「以下に〜について」
- 「ここで重要なのは」
- 「興味深いことに」
- 「ぜひ言っておきたいのは」
- 「あらかじめ言っておくと」
- 「先に断っておくと」
- 「ちなみに」
- 「なお、」（文頭の補足）

→ すべて削除し、内容を直接書く。

## 強調の松葉杖（Emphasis Crutches）

意味を加えていない強調句。

- 「重要なのは」
- 「特筆すべきは」
- 「強調すると」
- 「だからこそ」
- 「ここがポイント」
- 「ここが面白い」
- 「ここで注目したいのは」
- 「忘れてはならないのは」
- 「念のため言うと」
- 「言わずもがな」

→ 削除する。本当に重要なら文構造で示す。

## 副詞（Adverbs）

意味を加えていない副詞。原則全削除。

### 強調系
- 「とても」
- 「まさに」
- 「本当に」
- 「真に」
- 「決定的に」
- 「深く」
- 「強く」

### 限定系
- 「単に」
- 「ただ」
- 「ただ単に」
- 「ひたすら」

### 評価系
- 「実は」
- 「実際」
- 「実質的に」
- 「本質的に」
- 「本来」
- 「結局」
- 「最終的に」
- 「素直に」
- 「正直」
- 「単純に」
- 「必然的に」
- 「自然と」

### 関心引き系
- 「興味深いことに」
- 「重要なことに」
- 「驚くべきことに」
- 「面白いことに」
- 「予想通り」

→ 副詞のほとんどは削除可能。残すのは意味を変える限定的な場合のみ。

## ビジネス・ジャーゴン（Business Jargon）

カタカナ濫用と抽象表現の置換候補。

| 避ける | 使う |
|:---|:---|
| ナビゲートする | 対処する、進める |
| アンパックする | 整理する、解説する |
| リーンする / lean into | 受け入れる、取り組む |
| ランドスケープ | 状況、領域 |
| ゲームチェンジャー | 重要な転換点、決定的変化 |
| ダブルダウン | 強化する、増やす |
| ディープダイブ | 深掘り、詳細分析 |
| ステップバック | 立ち戻る、再考する |
| ムービングフォワード | 今後、次に |
| サークルバック | 戻る、再訪する |
| オンザセイムページ | 一致している、認識を合わせる |
| エンゲージメント | 参加、関与、反応 |
| インサイト | 知見、気づき |
| コミットメント | 約束、責任、関与 |
| アラインメント | 一致、整合 |
| シナジー | 相乗効果 |
| パラダイムシフト | 大きな転換 |

→ 日本語訳を併記し、初出のみカタカナを使う。

## メタコメント（Meta-Commentary）

記事自身の構造に言及する自己参照句。本文を流れさせる。

- 「ここから〜していきたい」
- 「この節では」
- 「以下で見ていく」
- 「あらかじめ言っておくと」
- 「メッセージは短くまとまる」
- 「結論は単純だ」
- 「言いたいことは 1 つ」
- 「順を追って説明する」
- 「ここまでをまとめると」
- 「以上を踏まえて」

→ 削除する。記事は announce せずに move する。

## 怠惰な極論（Lazy Extremes）

具体性のない sweeping claims。

- 「常に」
- 「いつも」
- 「全て」「すべて」
- 「決して」
- 「すべての」
- 「皆」「皆が」「皆さんが」
- 「誰もが」
- 「絶対に」
- 「100%」（強調文脈）
- 「いかなる〜も」

→ 具体的な範囲・条件に置換する。「常に〜」→「7 割の場合〜」。

## 曖昧な断定（Vague Declaratives）

具体を伴わない抽象だけの宣言。

- 「本質的に重要だ」
- 「構造的な問題だ」
- 「示唆は深い」
- 「実装上の課題」
- 「根本的な変革」
- 「重要な転換点」
- 「大きな意味を持つ」
- 「深い意味がある」
- 「考えさせられる」
- 「示唆に富む」

→ 具体的な内容を述べるか、その文を削除する。

## 締めの定型句（Closing Cliches）

記事末尾の使い回し句。

- 「参考になれば幸いです」
- 「ぜひ試してみてください」
- 「まずは小さく始めましょう」
- 「ご意見お待ちしています」
- 「皆さんはどう思いますか」
- 「ぜひ気軽にお試しを」
- 「いかがでしたでしょうか」
- 「お役に立てれば嬉しいです」

→ 削除する。記事は内容で終わる。

## 安直なまとめ表現（Cliched Closures）

章末・記事末で読者に評価を押し付ける句。

### 陳腐な比喩
- 「両輪」「両翼」「2 本の柱」「2 本立て」「2 枚の翼」「車の両輪」
- 「車輪の再発明」「氷山の一角」「ブラックボックス」（記事末）

### 偶然の必然化
- 「揃った」「出揃った」「同じ日に揃った」「期せずして」「奇しくも」
- 「歴史が動いた」「点と点が線になる」

### 過剰意味付け
- 「象徴する」「物語る」「示唆する」「映し出す」「浮き彫りにする」「炙り出す」

### メタコメント型まとめ
- 「メッセージは短くまとまる」
- 「結論は単純だ」
- 「言いたいことは 1 つ」

→ 数字を最後の一語にする / 断定で終わる / 観察事実だけ並べる。

**許容**（誤検出回避）:
- 「受動的締め（〜が問われている / 試されている / 求められている）」
- 「時代論評（AI 時代の〜 / 〜時代の〜）」

これらは記事の主題を読者に投げ返す機能として有効。

## 演出的フラグメント（Performative Emphasis）

不自然な親密さの演出。

- 「creeps in」相当の「忍び寄る」
- 「I promise」相当の「断言する」「保証する」
- 「they exist, I promise」相当の「本当に存在する」

→ 演出を削除し、事実だけ書く。

## 「示すのではなく告げる」（Telling Instead of Showing）

困難や重要性を announce するだけで demonstrate していない句。

- 「これは本当に難しい」
- 「これがリーダーシップの本当の姿だ」
- 「これこそが X の本当の姿だ」
- 「actually matters / 真に重要」

→ 具体的に示す。announce しない。

## LLM っぽい空句（型）

LLM が大量生成する、論点を増やさず「ちゃんと書いている感」だけを付ける型。本書・本記事の術語（本質的複雑さ、回収、判断の配置など）を議論に使うのはよい。空虚な装飾として使うのが問題である。

### 予告と総括

- 「重要なのは〜である」
- 「本章では〜を扱う／探求する」
- 「ここでは〜について見ていく」
- 「まとめると」「要するに」（直前の言い換えだけのとき）
- 「〜に他ならない」

→ 削除する。主張は予告せずそのまま書く。ただし様式の宣言（「標語として言い換えれば」など）は使ってよい。

### 正面から系

姿勢だけを宣言して中身を代替する句。

- 「正面から扱う」
- 「正面から回収する」
- 「正面から見る／書く／立てる」

→ 何をどう扱うかを直接書く。「正面から扱う」を消して「扱う」にする。

### 空虚な形容

主張の中身を説明せず強調だけする語。

- 「不可欠」「核心的」「鍵となる」「根本的な」
- 「多角的」「包括的」「総合的」（何をどう見たかを書かない）

→ 何が不可欠か、どう包括的かを具体に書く。書けないなら削除する。

### 空虚な動詞

何をどう書いたかを示さず終わる語。

- 「掘り下げる」「深掘りする」「言語化する」
- 「触れる」「言及する」（一段落で済ませるだけのとき）

→ 実際に書いた内容で示す。「掘り下げる」と言わずに掘り下げた中身を出す。

### 接続の型

新情報を足さない接続。

- 「〜において」「〜という側面から」「〜の観点から」
- 「さらに」「また」「加えて」の連打

→ 接続表現は前段落との論理関係を示すときだけ使う（「であれば」「実際」「しかし」）。

**悪い例**: 「本章では、〇〇の理論を正面から扱う。多角的に分析すると、重要なのは〜である」
**良い例**: 「本章では、〇〇の理論を扱う。評価の核心は、正しさを誰が知っているかにある」

## 翻訳調の AI 語（Translation-Style AI Vocabulary）

英語からの直訳調・学術翻訳調の漢語 2 字熟語結合。AI / LLM が好む「漢語的に厳めしいが意味は薄い」語彙。日本語の自然な会話・文章では「動詞 + 副詞」「ひらがな + 漢語 1 つ」のリズムが優勢。

### 命題・主張系
| 避ける | 使う |
|:---|:---|
| 中心命題 | 軸、核、主張、ポイント、要点 |
| 主要命題 | 主張、要点 |
| 命題は〜だ | （引用文を独立段落で出す）/ 軸は〜 |
| 主旨は〜だ | 要は〜、簡単に言えば〜 |

### 手順・実装系
| 避ける | 使う |
|:---|:---|
| 具体手順 | 具体的な手順、進め方、やり方 |
| 実装手順 | 作り方、組み立て方 |
| 構築手順 | 作り方、立ち上げ方 |
| 適用手順 | 当てはめ方、使い方 |

### 位置付け・接続系
| 避ける | 使う |
|:---|:---|
| 位置付け（られる）| 〜にあたる、〜として扱う |
| 位置付けする | 〜と並べる、〜の系譜にある |
| 〜に位置する | 〜にある、〜にあたる |
| 接続する設計図 | つながる図、連動の図 |
| 接続するアーキテクチャ | 組み合わせの仕組み |

### 構造・体系系
| 避ける | 使う |
|:---|:---|
| 体系化（する）| まとめる、整理する、組み立てる |
| 概念化（する）| 言葉にする、整理する |
| 構造化された〜 | 整った〜、組み立てた〜、筋の通った〜 |
| 体系的な | 整った、筋の通った |

### 方向・性質系
| 避ける | 使う |
|:---|:---|
| 方向性 | 方向、向き、進路、狙い |
| 方向感 | 向き、進路 |
| 方向付け | 向きを決める、進路を示す |
| 〜にあたって | 〜のとき、〜の前に、〜では |
| 〜性（即時性 / 機動性 等）| 動詞化「すぐに動く」「動きを速める」 |
| 〜化（可視化 / 自動化 等）| 動詞化「見えるようにする」「自動でやる」|

### 判定基準

「漢語 2 字 + 漢語 2 字」の結合が **1 段落 3 件以上**ある場合に削減する。または「英語の academic style から直訳した雰囲気」を感じたら 1 件でも書き換える。

### 根拠

2026-05-27 Varick 記事 X 宣伝スレッド執筆中、ユーザーが「中心命題は不自然な日本語」と指摘。ユーザー差し戻し 4 ラウンドで「中心命題 → 軸 → 引用文を独立段落で出す」に到達。「具体手順です」「位置付けられる記事」も同種の翻訳調として削除した。

日本語ネイティブの直感では「中心 + 命題」のような漢語 4 字結合は学術論文・法律文書の語彙であり、ソーシャル投稿や記事のリードでは違和感を生む。AI 生成物の検出シグナルとして高精度。

## 用語と register の自然さ（2026-06 W26 校正リトロ）

翻訳調 judge（S1-S4 の語レベル直訳）も機械チェック（禁止語）も通過するが、人手の校正で必ず引っかかる 4 類型。grep ではなく目視で点検する。

### 用語のさじ加減（括弧説明 vs 言い換え vs 無説明）

真に難解な語は括弧で補うより言い換える。一般語・直後で分かる語には説明を付けない。

| 過剰/不足 | 修正 |
|:---|:---|
| 重み（説明なしで不可読）| 学習済みモデル本体（重み）|
| Genie Ontology（オントロジー。データや…の地図）| Genie Ontology（直後の文で説明されるなら括弧は不要）|
| 半導体（AI の計算に使う高性能チップ）| 半導体（一般語。説明過剰なので削る）|

判定: 1 段落に括弧説明が 3 件以上あれば過剰。非エンジニアに通じない語だけ、最短の言い換えで補う。

### 製品名・固有名のカタカナ化

| 避ける | 使う |
|:---|:---|
| ジーニー | Genie |
| コーデックス | Codex |
| データブリックス | Databricks |

同一記事内で表記を揃える。「スキル」「エージェント」のような定着した一般概念カタカナは対象外。

### 比喩・言い回しの直訳

英語の比喩をそのまま訳さない（翻訳調 judge は語レベルのみで拾えない）。

| 避ける | 使う |
|:---|:---|
| 生きたグラフ（living graph）| 絶えず更新されるグラフ |
| （定着訳）堀（moat）| そのまま可 |

### 硬い書き言葉（book-ish register）

記事・note では書き言葉に寄りすぎた語を口語的に。技術書原稿はこの限りでない（register-aware）。

| 硬い | note 向け |
|:---|:---|
| 通底する | 共通する / 一貫して流れる |
| 降りてくる（製品が下位プランへ）| 使えるようになる |
| 価格 | 値段 |
| 〜へ移る | 〜へ動く / 移っていく |
| 中身が強い | 性能が高い |

**根拠**: 2026-06-21 AI週報 W26 で、記事 9 + 投稿 2 ≈ 11 ラウンドの差し戻し。翻訳調 judge 🟢pass・機械チェック通過後も、用語のさじ加減（重み/オントロジー/半導体）・製品名カタカナ（ジーニー）・比喩の直訳（生きたグラフ）・硬い書き言葉（通底/降りてきた/価格）が人手校正で全て指摘された。語レベルの自動チェックの守備範囲外であることが判明した。

# 翻訳調ジャッジ（LLM judge ルーブリック）

英語からの直訳調（translationese）を **語リストの列挙ではなく原理で判定する** ためのルーブリック。

## なぜ語リストではなく LLM judge か

直訳調は **無限に新パターンが生まれる**。「硬い上限（hard cap）」を語リストに足しても、次は「着地する（land）」「種付け（seed）」「露出する（expose）」が漏れる。いたちごっこになる。

そこで、**「この文は英語の直訳に読めるか？」を LLM に各文で判定させる**。判定は閉じた語リストではなく、下記の原理シグナルで行う。語例は **あくまで例示** であり、判定基準そのものではない。

## 判定対象から除外するもの

- コードブロック（``` で囲まれた範囲）とインラインのコマンド・識別子
- 固有名詞・製品名・技術 ID（OpenClaw / Hermes / Mem0 / FAISS / MCP 等）
- 定着した借用語（API / SDK / ストリーミング / サポート / ブロック / インデックス / キャッシュ 等、日本語 IT 文書で自然に使われるもの）
- 意図的な英語併記（「prefix caching（先頭キャッシュ）」のような説明付き）

## 判定シグナル（原理）

### S1. 英語動詞の逐語置換

英語の動詞を、文脈を無視して 1 対 1 で漢語・カタカナに置き換えたもの。元の英語が透けて見える。

- expose → 「露出する」（自然: 備える / 公開する / 持つ）
- ship → 「出荷する」（自然: 提供する / 同梱する / リリースする）
- seed → 「種付けする」（自然: セットする / 初期化する / 仕込む）
- land (on) → 「着地する」（自然: 届く / 到達する / 渡る）
- surface → 「浮上させる」（自然: 見つける / あぶり出す）
- drain → 「排出する」（自然: 流し込む / 吸い出す）
- pin → 「ピンする」（自然: 固定する）
- capture → 「キャプチャする」（文脈次第: 取り込む / 記録する）

判定の核: **その動詞は日本語ネイティブが同じ状況で自然に選ぶ動詞か**。英語の原語を当てれば 1 対 1 で戻せる場合は直訳調の疑い。

### S2. 英語形容詞の直訳

英語の形容詞を逐語で訳し、日本語として浮く修飾。

- hard (cap / limit) → 「硬い上限」（自然: 厳格な上限 / 上限）
- live (memory) → 「生きているメモリ」（自然: 動的なメモリ / ライブなメモリ）
- rich (context) → 「豊かなコンテキスト」（自然: 情報量の多いコンテキスト）
- deep (integration) → 「深い統合」（文脈次第: 緊密な統合）

判定の核: **その形容詞 + 名詞の組み合わせが日本語の慣用に存在するか**。英語の collocation をそのまま移したものは疑い。

### S3. 英語構文のなぞり

英語の定型構文を語順ごと移植したもの。

- "X is nothing but Y" → 「X は Y に過ぎない」の機械的多用
- "It's worth noting that" → 「〜は注目に値する」
- "That said" → 「そうは言っても」（文頭の癖）
- "the fact that" → 「〜という事実」の冗長な使用

判定の核: **日本語として書き起こすときに自然に出てくる構文か**、英語を下敷きにした翻訳調か。

### S4. 英語慣用句の逐語訳

イディオムを意味ではなく字面で訳したもの。

- "at the end of the day" → 「一日の終わりに」（自然: 結局 / 最終的に）
- "moving forward" → 「前進して」（自然: 今後 / これから）
- "low-hanging fruit" → 「低く垂れ下がった果実」（自然: 手近な成果）
- "on the same page" → 「同じページに」（自然: 認識を合わせる）

## LLM への指示（judge プロンプトの骨子）

> あなたは日本語の編集者です。以下の日本語テキストを 1 文ずつ読み、**英語からの直訳に読める箇所** を検出してください。
>
> - 判定は上記 S1〜S4 の原理で行う。語リストの暗記ではなく「日本語ネイティブが同じ状況で自然にこう書くか」で判断する
> - 除外対象（コード / 固有名詞 / 定着借用語 / 説明付き英語併記）は flag しない
> - 各検出について、flag した語句・原因シグナル・自然な日本語の代替案・確信度（high / medium / low）を返す
> - 確信度 high = 明確に英語直訳、medium = やや不自然、low = 文脈次第で許容も
> - 自然で問題ない文は flag しない。**過剰検出を避ける**

## 出力スキーマ

```json
{
  "flags": [
    {
      "excerpt": "文字数の硬い上限は 2,200",
      "signal": "S2",
      "english_source": "hard cap",
      "suggestion": "文字数の上限は厳格に 2,200",
      "confidence": "high"
    }
  ],
  "summary": {
    "high": 1,
    "medium": 0,
    "low": 0
  },
  "verdict": "needs_revision"
}
```

- `verdict`: high が 1 件以上なら "needs_revision"、medium のみなら "review"、すべて low か 0 件なら "pass"

## 運用

- リライト完了後、本ルーブリックで LLM judge を 1 回実行する
- `verdict == "needs_revision"` なら high の flag を全て修正してから再 judge
- スクリプト実装は [scripts/judge-translationese.mjs](../scripts/judge-translationese.mjs) を参照（provider 切替式）
